MINETUNES - CURSEFORGE PAGE TEXT
================================
Companion to modrinth-description.txt. Same mod, written for CurseForge's forms:
no Markdown tables (they render badly there), a 255-char summary, and a changelog
block because CurseForge asks for one per uploaded file.


SUMMARY  (the "Summary" field - 132 chars on one line, limit is 255)
--------------------------------------------------------
A now-playing card on your HUD that controls whatever Windows is already playing -
Spotify, YouTube, a podcast, a video. No alt-tab.


DESCRIPTION  (the "Description" field, which renders Markdown)
--------------------------------------------------------------
MineTunes puts a now-playing card on your HUD and lets you drive it without leaving the game.

It reads the **Windows SMTC media session** - the same one your keyboard's media keys and the
volume flyout use - so it is not tied to any one player. Whatever Windows says is playing is what
the card shows.

**Requirements**

- Minecraft 1.21.11, 26.1.2, 26.2 or 26.3 - one jar per version, pick the file that matches your game
- Fabric Loader 0.19.2 or newer (0.19.3 or newer for the 26.x builds)
- [Fabric API](https://www.curseforge.com/minecraft/mc-mods/fabric-api) (required, same version as the game)
- Java 21 or newer (Java 25 on 26.x)
- Windows 10 or 11 - SMTC is a Windows feature, so there is nothing to control on other systems
- Network is optional: only the lyrics lookup uses it, and `/music lyrics off` turns that off

Mod Menu is optional: the mod runs and is fully configurable without it, and only gains a config
button in the mod list when it is installed.

**What it does**

- A now-playing card: album sleeve, title, artist and album, elapsed time, progress bar and four
  transport buttons.
- Play / pause, previous, next, seek, shuffle and repeat, through the session the OS media keys use.
- Album art pulled from the session, with the panel's accent colour picked off the cover.
- Text that does not fit slides instead of being cut off.
- Drag the card anywhere on screen. Park it past the middle and it mirrors to face that corner.
- The buttons answer clicks while another screen is open - inventory, chat, Mod Menu - so you can
  skip a track without closing what you were looking at.
- Six keybinds in their own **MineTunes** category, rebindable in vanilla Controls or the mod's own
  settings screen.
- **Decks**: community-made looks in a plain JSON file. No code, no rebuild, and a dropped-in file
  shows up the next time you open the picker.
- **Lyrics**: the card shows the line being sung, in a small panel under it. A `.lrc` you save in
  `config/musicdeck/lyrics/` is always used first; a track with no file is looked up once on
  lrclib.net and the answer is saved in that folder, so the next play works offline. `/music lyrics
  off` turns the lookup off and the mod then makes no request at all.

**Commands**

`/music` and `/minetunes` do the same thing.

```
/music status                      what the session says right now
/music play | pause | toggle
/music next | prev
/music seek <seconds>
/music shuffle [on|off]
/music repeat [none|track|playlist]
/music hud [x y]                   show, hide, or place the card
/music move                        the drag screen
/music style [smooth|pixel]        how the album art is scaled
/music theme [auto|green|white]    panel colour
/music deck [name]                 which deck to draw with
/music lyrics                      whether the playing track has words, and where they go
/music lyrics on | off             turn the lrclib.net lookup on or off
/music settings                    the settings screen
/music restart                     re-launch the media helper
```

**Files it writes**

- `<game dir>/musicdeck.properties` - position, deck, theme, art style, visibility, the `onlineLyrics` switch
- `<game dir>/config/musicdeck/decks/` - your decks; three examples are seeded on first run
- `<game dir>/config/musicdeck/lyrics/` - your `.lrc` files and every lyric the lookup found; one
  example is seeded on first run

Client-side only. It registers no URL handler, needs no admin rights, and other players see nothing.

Under the hood it launches Windows' own PowerShell as a helper process, which asks the local Windows
media-session API what is playing and writes the answer to `<game dir>/musicdeck/`. Its only network
traffic is the lyrics lookup: when a track has no local file and online lyrics is on, it sends an
HTTPS GET to lrclib.net carrying the artist, the title and the track's length, and saves the answer
in the lyrics folder. Nothing else leaves the machine, there is no telemetry, and `/music lyrics
off` stops the lookup entirely. No registry changes, no elevation.

**Known limits**

These are ceilings in the SMTC contract, not bugs:

- **No volume verb.** The session exposes play, pause, skip and position, so the mod can seek but
  cannot change your volume.
- **Shuffle and repeat are often hidden.** Many players report neither verb as supported, so the
  repeat button can do nothing. The mod sends the request and reports what the session said; it
  cannot make a player obey.
- **The session follows whoever took it last.** Starting a video in Chrome can steal it from your
  music app, and the card changes with it.
- **Position is extrapolated.** Some players only report a new position on a track change, so the
  bar estimates in between.
- **Artwork lags text** by up to a second on a track change - the thumbnail arrives after the title.
- **Lyrics can be missing or mistimed.** The session carries a title, an artist and a position, never
  the words, and Spotify keeps its lyrics inside its own window. The panel reads your `.lrc` files
  first and only then asks lrclib.net, so an obscure track, an offline machine or a switched-off
  lookup leaves a track with no panel. Timings come from whoever wrote the file, so a live take or a
  remaster can drift from the audio.
- **Click-through is the least proven part.** The card is drawn on the HUD, so its buttons only
  receive a click when another screen is open. The keybinds and `/music` go through the same verbs
  and do not depend on it.


CHANGELOG  (the "File changelog" field - the same text goes on every 1.1.0 file)
------------------------------------------------------------------------------
First release.

- Now-playing card on the HUD: album sleeve, title, artist, album, elapsed time, progress bar and
  four transport buttons.
- Play / pause, previous, next, seek, shuffle and repeat over the Windows SMTC session.
- Album art from the session with the panel accent picked off the cover; smooth and pixelated
  scaling.
- Slide-to-read text instead of truncation.
- Drag-anywhere placement; the card mirrors to face whichever side it is parked on.
- Transport buttons clickable while another screen is open.
- Six rebindable keybinds in their own MineTunes category, plus a settings screen and Mod Menu entry.
- Community decks: JSON files in `config/musicdeck/decks/`, three examples seeded.
- Synced lyrics: your own `.lrc` files first, with a one-time lrclib.net lookup for tracks that have
  none, saved into the lyrics folder so the next play works offline.
- Commands `/music` and `/minetunes`.


HOW TO FILL IN THE CURSEFORGE FORM
----------------------------------
- Category: Mods, then Fabric.
- Game version: tick only the one the file you are uploading was built for - 1.21.11, 26.1.2, 26.2
  or 26.3. Mod loader: Fabric. Environment: Client.
- License: MIT.
- Relations: Fabric API = Required dependency. Mod Menu = Optional dependency.
- Upload the file from `releases/` whose name matches that game version
  (`minetunes-1.1.0.jar`, `minetunes-1.1.0+26.1.2.jar`, `+26.2`, `+26.3`), release type **Release**,
  and paste the changelog above. Each is a separate file entry; do not tick several game versions on
  one file. The .jar already carries the 128px icon, so CurseForge's own icon upload is only for the
  project page.
- Logo: `publish/minetunes-icon.png`. Screenshots: `docs/card-left.png`, `docs/card-right.png`
  (the same card parked on opposite sides) and `docs/lyrics.png` (the lyric panel).
- `version-description-1.21.11.txt`, `-26.1.2.txt`, `-26.2.txt`, `-26.3.txt` are one file per
  version: the CHANGELOG in each is written for this field on that file, and the DESCRIPTION stands
  alone if you ever split the project per version.
- Leave out the source link for now - the GitHub repo has not been created or pushed yet.
